    강사용 시연 가이드

    바이브 코딩으로 MkDocs + GitHub Pages 라이브 시연 (90분)

    이 문서는 강사가 시연 중에 참고하는 진행 가이드입니다. 각 스텝별 예상 시간, 할 일, 말할 포인트가 정리되어 있습니다.

    시연 전 체크리스트

    시연 시작 전에 아래 환경이 준비되어 있어야 합니다:

    • [x] Git 설치 확인 (git --version)
    • [x] Python 설치 확인 (python --version)
    • [x] VS Code 설치 및 실행
    • [x] GitHub 로그인 상태
    • [x] Git Bash 열어두기
    • [x] 브라우저 열어두기 (GitHub, AI 채팅)
    • [x] AI 채팅 창 열어두기 (ChatGPT 또는 Claude)
    • [x] 화면 공유 또는 프로젝터 연결 확인

    시연용 GitHub 저장소

    시연 전에 기존 demo-docs 저장소가 있다면 미리 삭제하세요. 매번 새로 만드는 과정을 보여줘야 합니다.

    전체 흐름 (90분)

    순서 스텝 시간 핵심 메시지
    1 오프닝: 바이브 코딩이란? 5분 "코드를 몰라도 됩니다"
    2 사전 준비 도구 소개 5분 "4가지만 설치하면 끝"
    3 프로젝트 생성 10분 "명령어 3줄이면 프로젝트 완성"
    4 AI에게 설정 파일 요청 15분 "바이브 코딩의 핵심: AI에게 물어보기"
    5 마크다운 문서 작성 10분 "글만 쓸 줄 알면 됩니다"
    6 로컬 미리보기 5분 "내 컴퓨터에서 바로 확인"
    7 GitHub 저장소 + 배포 20분 "인터넷에 공개되는 순간"
    8 실제 사이트 접속 확인 5분 "이제 누구나 볼 수 있습니다"
    9 문서 추가 시연 10분 "문서 추가도 이렇게 쉽습니다"
    10 마무리 + Q&A 5분 "가이드 문서 배포, 집에서 해보세요"

    Step 1: 오프닝 (5분)

    할 일

    • 바이브 코딩 개념 설명

    말할 포인트

    "바이브 코딩이란 AI에게 자연어로 설명하면 AI가 코드를 만들어주는 방식입니다. 코드를 모르셔도 됩니다. 물어보고, 복사하고, 붙여넣으면 됩니다. 지금부터 90분 동안 실제로 문서 웹사이트를 하나 만들어보겠습니다. 여러분도 집에 가셔서 똑같이 따라하실 수 있도록 가이드 문서를 드릴 겁니다."

    참고

    • 앞서 진행한 Cline 실습(CSV → Streamlit 시각화)과 연결: "아까는 사내 AI로 데이터 시각화를 해봤고, 이번에는 외부 AI로 문서 사이트를 만들어보겠습니다"

    Step 2: 사전 준비 도구 소개 (5분)

    할 일

    • 설치할 4가지 도구를 간략히 소개 (직접 설치하지는 않음, 이미 되어있으므로)
    • 버전 확인 시연

    시연 명령어

    git --version
python --version
node --version

    말할 포인트

    "이 4가지 — Git, Python, VS Code, GitHub 계정 — 만 있으면 됩니다. 설치 방법은 가이드 문서에 자세히 적어뒀으니 집에서 따라하시면 됩니다. 설치할 때도 막히면 AI한테 물어보면 다 알려줍니다."

    Step 3: 프로젝트 생성 (10분)

    할 일

    1. 작업 폴더 생성
    2. MkDocs 설치
    3. 프로젝트 초기화
    4. 생성된 파일 구조 확인

    시연 명령어

    cd ~
mkdir demo-docs
cd demo-docs
pip install mkdocs mkdocs-material
mkdocs new .

    VS Code에서 보여줄 것

    • File → Open Folder → demo-docs 선택
    • 왼쪽 파일 트리에서 mkdocs.yml과 docs/index.md 클릭하여 보여주기

    말할 포인트

    "5줄 명령어로 프로젝트가 만들어졌습니다. 파일이 딱 2개입니다: 설정 파일(mkdocs.yml)과 첫 번째 문서(index.md). 이게 전부입니다. 이제 여기에 내용을 채우면 됩니다."

    Step 4: AI에게 설정 파일 요청 (15분)

    이 스텝이 바이브 코딩의 하이라이트입니다. 천천히, 실제로 AI와 대화하는 모습을 보여주세요.

    할 일

    1. AI 채팅 창을 화면에 보여주기
    2. 프롬프트 입력 (직접 타이핑하거나 미리 준비)
    3. AI 답변 기다리기
    4. 답변을 복사하여 mkdocs.yml에 붙여넣기

    AI에게 보낼 프롬프트

    MkDocs Material 테마로 기술 문서 사이트를 만들고 있어.
아래 조건에 맞는 mkdocs.yml 파일 내용을 만들어줘.

조건:
- 사이트 이름: "HW팀 기술 노트"
- 한국어 검색 지원
- 다크모드/라이트모드 전환 가능
- 코드 복사 버튼 활성화
- 네비게이션 탭 사용
- nav 구조:
  - 홈: index.md
  - 가이드:
    - 장비 세팅: guides/equipment-setup.md
  - 메모:
    - 첫 번째 메모: notes/first-note.md

    시연 순서

    1. AI 채팅 창에 프롬프트 입력 → 전송
    2. 답변이 오는 동안 청중에게 설명:

      "지금 AI에게 설정 파일을 만들어달라고 했습니다. 제가 한 건 제 요구사항을 글로 적은 것뿐입니다. 코드를 한 줄도 직접 쓰지 않았습니다."

    3. AI 답변이 오면 코드 블록의 복사 버튼 클릭
    4. VS Code에서 mkdocs.yml 열기 → 전체 선택(Ctrl+A) → 붙여넣기(Ctrl+V) → 저장(Ctrl+S)

    추가 시연: 문서 내용도 AI에게 요청

    MkDocs용 마크다운 파일 3개를 만들어줘.

1. docs/index.md - HW팀 기술 노트 홈페이지. 환영 인사와 사이트 소개.
2. docs/guides/equipment-setup.md - 신규 장비 초기 세팅 가이드 예시.
3. docs/notes/first-note.md - 오늘 배운 바이브 코딩 소감 메모.

각 파일마다 적절한 제목과 내용을 넣어줘. 마크다운 형식으로.

    말할 포인트

    "이게 바이브 코딩입니다. 제가 한 건 '이렇게 만들어줘'라고 글을 쓴 것뿐이고, AI가 설정 파일과 문서 내용을 전부 만들어줬습니다. 저는 복사해서 붙여넣기만 했습니다."

    Step 5: 마크다운 문서 작성 (10분)

    할 일

    1. 폴더 구조 생성
    2. AI가 만들어준 문서를 각 파일에 붙여넣기
    3. 마크다운 기본 문법 간단 설명

    시연 명령어

    mkdir -p docs/guides
mkdir -p docs/notes

    VS Code에서 보여줄 것

    • 각 파일을 만들고 AI 답변 내용 붙여넣기
    • 마크다운의 #, -, **, | 등이 어떻게 렌더링되는지 설명

    말할 포인트

    "마크다운은 간단합니다. #은 제목, -는 목록, **은 굵게. 사실 이것도 몰라도 됩니다. AI한테 '마크다운으로 만들어줘'라고 하면 알아서 다 해줍니다."

    Step 6: 로컬 미리보기 (5분)

    할 일

    1. mkdocs serve 실행
    2. 브라우저에서 확인
    3. 실시간 수정 반영 시연

    시연 명령어

    mkdocs serve

    시연 순서

    1. 브라우저에서 http://127.0.0.1:8000 접속 → 사이트 보여주기
    2. VS Code에서 index.md의 제목을 수정하고 저장
    3. 브라우저가 자동으로 업데이트되는 것을 보여주기
    4. 다크모드 토글 버튼 클릭해서 보여주기
    5. Ctrl+C로 서버 종료

    말할 포인트

    "내 컴퓨터에서 바로 확인할 수 있습니다. 수정하면 실시간으로 반영됩니다. 미리보기 하면서 계속 다듬을 수 있습니다. 이제 이걸 인터넷에 올려보겠습니다."

    Step 7: GitHub 저장소 + 배포 (20분)

    이 스텝이 가장 길고 복잡합니다. 천천히 하나씩 보여주세요.

    할 일

    1. GitHub에서 저장소 생성 (브라우저)
    2. Git 초기화 및 push (Git Bash)
    3. GitHub Actions 배포 설정 (AI에게 요청)
    4. Push 후 Actions 실행 확인

    7-1. GitHub 저장소 생성 (브라우저에서)

    • https://github.com → + → New repository
    • Repository name: demo-docs
    • Public 선택
    • Create repository 클릭

    7-2. Git push (Git Bash에서)

    git init
git add .
git commit -m "첫 번째 커밋: MkDocs 프로젝트 생성"
git branch -M main
git remote add origin https://github.com/본인아이디/demo-docs.git
git push -u origin main

    7-3. GitHub Actions 설정

    AI에게 요청:

    GitHub Actions로 MkDocs를 자동 배포하는 워크플로우 파일을 만들어줘.
main 브랜치에 push하면 자동으로 mkdocs gh-deploy 실행.
파일 경로: .github/workflows/deploy.yml

    AI 답변을 받아서 파일 생성:

    mkdir -p .github/workflows

    VS Code에서 .github/workflows/deploy.yml 만들고 AI 답변 붙여넣기.

    git add .
git commit -m "자동 배포 설정 추가"
git push

    7-4. GitHub Pages 설정 (브라우저에서)

    1. GitHub 저장소 → Settings → Pages
    2. Source: Deploy from a branch
    3. Branch: gh-pages / / (root)
    4. Save

    말할 포인트

    "GitHub는 무료로 웹사이트를 호스팅해줍니다. 한번 설정해두면, 이후에는 문서를 수정하고 push만 하면 자동으로 사이트가 업데이트됩니다."

    시연 중 주의

    GitHub Actions 실행에 1~2분 걸립니다. 기다리는 동안 Actions 탭을 보여주면서 진행 상황을 설명하세요. "지금 GitHub 서버에서 자동으로 빌드하고 배포하고 있습니다."

    Step 8: 실제 사이트 접속 확인 (5분)

    할 일

    1. 배포된 사이트 접속
    2. 청중과 함께 확인

    시연

    • 브라우저에서 https://본인아이디.github.io/demo-docs/ 접속
    • 문서들이 제대로 보이는지 확인
    • 다크모드 전환, 검색 기능 등 시연

    말할 포인트

    "10분 전에는 존재하지 않았던 사이트가 지금 인터넷에 올라와 있습니다. 제가 직접 코드를 쓴 건 거의 없습니다. AI에게 물어보고, 복사하고, 붙여넣기만 했습니다."

    Step 9: 문서 추가 시연 (10분)

    할 일

    1. AI에게 새 문서 요청
    2. 파일 추가 + mkdocs.yml 수정
    3. push → 자동 배포 → 확인

    AI에게 보낼 프롬프트

    우리 팀의 주간 회의록 마크다운 템플릿을 만들어줘.
