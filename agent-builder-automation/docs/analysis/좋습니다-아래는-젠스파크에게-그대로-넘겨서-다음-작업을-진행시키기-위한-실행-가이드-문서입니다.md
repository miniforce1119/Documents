## 1. 프로젝트 개요

이 프로젝트의 목적은 AI가 생성한 유용한 답변을 문서 자산으로 축적하는 시스템을 만드는 것이다.

초기에는 사내 Wiki(Confluence)로 직접 변환하는 방향을 검토했지만, AI가 생성한 Markdown과 Wiki 포맷 간의 불일치, 렌더링 문제, 자동화 복잡도 때문에 방향을 조정했다.


### 현재 목표는 다음과 같다.


AI 답변을 Markdown 문서로 정리하고, 이를 GitHub Enterprise + MkDocs 기반 Docs Site에 축적하는 문서화 시스템을 구축한다.


### 이 시스템은 단순 저장기가 아니라,


### 유용한 AI 결과를 선별하고 정규화하고 발행하는 문서 검토/발행 시스템이어야 한다.



## 2. 핵심 철학


### 이 시스템에서 가장 중요한 데이터는 AI로부터 생성된 데이터다.



### 즉, 문서화 대상의 중심은 다음이다.



### 사내 Agent Builder 전용 AI Agent가 생성한 결과



### 사외 AI(ChatGPT, Claude 등)가 생성한 결과

### 핵심 철학은 다음과 같다.



### 이 도구는 Markdown 에디터가 아니라,


### AI 생성 지식을 문서 자산으로 변환하는 도구다.

## 5. 왜 두 입력 모드를 모두 지원해야 하는가


### 이 툴은 더 이상 단순히 Agent Builder 결과 저장기가 아니다.



### 실제로는 아래 역할을 수행해야 한다.


여러 AI 소스에서 나온 유용한 결과를, 사내 표준 문서 형식으로 정규화하여 축적하는 시스템

### ...

### ...

## 6. Agent 설계 방향

### 결론



### 처음 단계에서는 Agent를 2개로 분리하는 것이 좋다.



### Agent 1. 질문용 Document Writer Agent



### 역할:



### 사용자의 질문을 받아



### 저장 가치가 있는 문서 형태로 새 문서를 생성



### TITLE / FILENAME / CONTENT 구조로 출력



### 입력 예:



### MkDocs와 GitHub Actions를 이용한 문서 자동화 workflow를 설명해줘



### 역할 특성:



### 새 문서를 쓰는 역할



### 설명 확장



### 배경/예시/결론 포함



### 완성형 Markdown 문서 생성



### Agent 2. Reformat Agent



### 역할:



### 사외 AI 결과나 자유형 텍스트를 입력받아



### 사내 표준 문서 포맷 Markdown으로 재구성



### TITLE / FILENAME / CONTENT 구조로 출력



### 입력 예:



### 외부 AI 복붙 텍스트



### 역할 특성:



### 원문 의미를 최대한 보존



### 구조화



### 제목/파일명 재설정



### Markdown 문서 포맷으로 재작성



### 왜 2개로 분리해야 하는가



### 한 개 Agent로 합치면 아래 문제가 생길 수 있다.



### 입력이 질문인지 재구성 대상 텍스트인지 모호해짐



### 문서 생성과 문서 재정리 역할이 섞여 품질 흔들림



### 디버깅 어려움



### 프롬프트 설계가 복잡해짐



### 따라서 초기에 2개로 나누고, 나중에 충분히 안정화되면 통합 여부를 판단하는 것이 좋다.
